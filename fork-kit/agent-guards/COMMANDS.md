# The kit's ready-made commands

`facts` reads this table with the machine's own (FACTS.md, The kit's commands), so `facts --index`, `facts <words>`
and the session-start hook list these commands on every machine with the kit, with no setting. Each runs from
`/usr/local/bin`; `<command> --help` gives its usage. Code: `lib/agent_guards/kitcmds.py`.

| Thing                                    | What we made / how to use it                                                                                                                                                                                                                                                                    | State now                                                                      | Why                                                                                 |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------- |
| fork-ci-why: why are a PR's checks red   | `fork-ci-why <pr> [-R owner/repo] [--all] [--lines N]`: each failing required check on the PR head, its job link and only its log's error lines (ANSI and timestamps stripped)                                                                                                                  | Needs `gh` signed in; exit 1 when it shows failing checks                      | One call instead of `gh pr checks`, a job id, `gh api .../logs`, a grep             |
| fork-clone: a new clone with its install | `fork-clone <name> [branch] [--repo URL] [--into DIR]`: blob-less clone at `$FORK_WORK_DIR` (else `~/work`)`/<name>`; offline install from the store when another clone there has the same `pnpm-lock.yaml`, else one install                                                                   | Run again: reuses a clone of the same repository; remakes one stopped half-way | Several turns of clone, compare lockfiles, install                                  |
| fork-precheck: check before a push       | `fork-precheck [--base REF] [--no-tests] [--no-fork-checks] [--kind KIND]`: `vp fmt` and `vp lint` on the files changed against the base; the schema, upstream-files and seam checks as fork-checks.yml runs them (failing lines only); then the touched test files, once `t3-capacity` says OK | Exit 3: capacity NOT OK, fmt and lint ran, no test did: run it again later     | CI reds on formatting and the fork checks; whole suites run where one file would do |
